# 模板内交互多样性

`interaction-design-v5` 先设计相遇关系，再联合设置初始位置、速度、队列间隔和动作时序。同景五分支冻结全部场景参数；模型历史仍为2秒、未来仍为4秒。`interaction_phase` 是采集前的设计分层，不能当作已经发生的 t0 状态或未来行为。

## 十二个模板

| 模板 | 设计分层 | 生成器实际变化 |
| --- | --- | --- |
| 后车跟驰 | 间距充足、接近、减速趋势、连续车流 | 后车实际路线站位、相对速度、目标速度、延迟制动时刻 |
| 自车直路变道 | 宽松间隙、后车接近、较紧间隙、较晚介入 | 真实邻道前后布局、后车接近速度、变道开始时刻；保留完成及保持时间 |
| 周车直路汇入 | 等待间隙、接近横移、开始切入、部分进入 | 冻结源/目标 Driving 走廊与最早意图时刻；实测前后间隙决定等待、横移、早期取消或重新确认，纵向跟车沿当前选定路线 |
| 周车匝道汇入 | ego先到、接近同时、NPC先到、持续车流 | 双方到达时间、独立初速、真实路线出生站位、后续间隔 |
| 自车匝道汇入 | ego先到、接近同时、主路先到、持续车流 | 主路前后间隙、双方相对速度与到达顺序 |
| 无信号路口直行 | 等待、起步、接近、进入 | 双方到达时间、初速、后续间隔；实际停走阶段由实时路权决定 |
| 有信号路口直行 | 队列释放、已经释放、早清空、晚清空 | 固定信号程序中横向绿灯相对 t0 的时刻、队列间隔 |
| 无信号路口左转 | 宽间隙、接近同时、对向先到、持续车流 | 对向初速、到达时间、车队间隔 |
| 有信号路口左转 | 较长绿灯、较晚绿灯、队列间隙、持续车流 | 实际映射信号的非保护左转条件、对向到达关系、剩余绿灯 |
| 直路行人过街 | 路缘等待、入区、穿越、接近清空 | 真实人行道起点、可行过街方向、步速、自然起步时间、后车布局 |

各模板的四个分层在任务规划时按模板轮转分配；地点、天气、风格仍分别统计。候选修正保留分层。地图长度或车身不允许的布局拒绝并记录，不把演员移到非 Driving 车道凑数。参与车辆数量、队列及个体参数由[联合随机生成](scene-randomization.md)采样；同时保存各车实际距离和速度。地图、动力学及通行判断可能使请求阶段没有达成，报告必须同时列出请求和实测状态。

## 行人和共同历史

`reactive_crossing_v4` 允许最早决策落在共同运动预热内。较早阶段从真实人行道自然走出，不能在 t0 瞬移到路中央。预热最长仍为3秒；保存模型输入之前的全部行人决策所用车辆/行人观测、命令、帧号和内部状态。验收从未起步状态复算预热，再接上 −2 秒的模型历史，并核对上一命令与原生读回控制。

模型使用的状态、六相机和LiDAR仍只保存 −2..4 秒的原定121物理帧/13传感器时刻。`pedestrian_decisions.json.warmup` 是审计证据，不扩大模型历史。公共历史、repeat、物理/视觉重放均检查行人内部状态延续。详见[行人策略](pedestrian-feedback.md)。

行人入区和穿越阶段联合生成名义步速、身体相对冲突区的进度、ego到达余量与加速动作的介入时刻/强度，保存在 `interaction_design.pedestrian_encounter`。这两类ego接近初速为3.0–4.3m/s；行走名义速度在任务规划时分为较慢1.0–1.2、常速1.2–1.5、较快1.5–1.8m/s三档，档内再采样。任务字段 `pedestrian_pace` 在每个模板的三轮四阶段分配中交叉均衡，确保12个计划槽位中的入区、穿越各覆盖三档步速；路缘等待和接近清空阶段维持原步速分布。旧显式job未写该字段时使用固定seed选择步速档，不读取采集结果。`interaction_design.pedestrian_pace` 记录请求档位、范围和抽样值，实际速度仍另报；这些档位是工程设计而非真人行为标定。加速策略目标为3.0–3.8m/s²、延迟在0～0.2秒连续采样，仍受原生车辆能力和速度增量上限限制，不把目标加速度称为实测值。先估计行人清空车辆横向走廊所需时间，再联合重排整个ego车流的位置；允许从旧模板位置向前或向后移动，原有延迟停车距离仍是硬约束。

名义起步机会还要用最早准备时刻的真实地图路线位置和朝向检查全过街扫掠，车辆保守半长/半宽2.8/1.15m，行人平面半宽0.3m，原谨慎余量不变。不满足时在编译阶段记录几何失败；这检查共同历史之前的布局机会，不模拟五种未来动作，也不要求某种行人后果。弯曲接近段不能只用“距路口多少米÷速度”冒充时序可行。行人从真实人行道经共同预热和历史自然运行到t0，不用直接设置已释放状态制造入区。规划估计不等于实际阶段，原生执行速度、起步等待和道路几何都可能使目标阶段没有达成。

## 通行与动作

行人 v3 用逐对象、逐时刻的车身扫掠检查代替单个覆盖整个过街过程的统一间隙。只有已经观测到后车制动、其同一路线前车已停住、前后车横向一致、制动距离留有余量且后车没有变道路线时，才使用当前减速度外推至停车；不能仅凭“前车应该挡住它”忽略后车。

窄路 `narrow-current-occupancy-v2` 先核对映射路线及当前车身横向间隔，使用实测车身朝向、局部包围框旋转与偏移投影车头、车尾和横向占用。可以错身时限制通过速度；确实不能错身时，已经占用通道的车辆先清空，入口等待方按固定优先条件和实际占用判断。解除阻挡后持续确认0.4秒，包括从不能错身变为可以错身的情况。该局部几何启发式不是全路线安全证明，接触仍由原生记录报告。

行人、无信号左转和窄路采用有显式延迟的 `stop_hold`：t0 选定完整策略，先继续一段时间，再按更短停止期限制动并保持。`yield_wait` 从t0开始较温和减速，指定对象身体清空且当前可通行才允许恢复。名称保留兼容性，真实语义以 `profiles` 中 onset、停止期限、设计制动能力及逐帧实测控制为准。其余模板保留更适合其几何的动作组合；不向所有模板强塞同一五动作。模型动作输入必须包含时序，不能只使用分支名称。设计制动能力不等于实测减速度，也不表示模拟了驾驶员感知迟滞。

所有新编译的 `stop_hold` 和 `yield_wait` 动作均显式配置 `terminal_brake_min=1`：进入停车末段（零目标速度或保持指令）后使用完整归一化制动命令，避免实车仍在运动时仅依赖默认0.4保持制动。此规则按动作 kind 应用，不按模板白名单应用；不含这两类停车/等待策略的动作组合不增加此字段。有信号左转、无信号左转、无信号直行及自车匝道汇入的原生失败记录均确认过同一末段停车超时问题。本次随机化开发另确认让行末段也可能因0.4制动停得过慢，因此同样声明该制动参数。它只作用于干预开始后的强制零速保持，不改变非零目标的提前减速、清空后的滚动恢复、共同历史或NPC；停止期限、保持宽限和动作区分门槛不变。它不是减速度单位或避碰保证，仍须原生验收停止时刻、减速度及全部动作对。未声明该字段的历史规格保持原控制行为，不追认新动作配置。

有信号场景必须按实际绑定的灯及停止线读回验收。横向放行模板仍是“ego 初态已过停止线、横向队列随后放行”的清空条件，不能据此声称观察到了合法入场；左转使用映射道路上的双向许可绿灯和对向让行。自定义控制器不等于 CARLA Traffic Manager。灯色/路权程序同景冻结，ego 显式干预可能不遵守它；风险条件需如实解释。

## 实测覆盖与初步验收

`reports/interaction_coverage_physics.json` 与 `interaction_coverage_capture.json` 保存：实测t0速度/位置/行人阶段、各对象路径、运动后停车、慢行、加快、反向退让、阻挡原因计数、每对象全部10对响应及 repeat 噪声。报告属于后果描述，不是按强反应挑选正式评测样本的门禁。

运动速度门槛0.05m/s，连续事件至少0.25秒；加快描述为超过名义步速的1.15倍，慢行为低于0.75倍。反向路程另计。0.5/1m对象差异是工程描述，不能替代repeat或因果证明。接触后的对象位移不自动解释为主动反馈。

`active_feedback` 将上一物理步的策略选择、当步原生已执行控制与实测运动对齐，只在首次分支接触前计数，且该策略片段须在t0之后新开始。主动停步需在本次stop策略选择时仍有实际行走、当前不是路线终点、策略为stop且原生命令/实测速度均接近零；退让需实际反向且反向路程超过5厘米；加快需fast模式、实际命令和速度均超过名义步速1.15倍；恢复需先有符合上述条件的实测停步或退让。所有事件持续至少0.25秒。不把历史状态延续、起步前等待、命令未执行、撞击位移或受障碍挡住算作新增主动反馈。

每段另记录 `paired_motion_evidence`：在事件持续期间，与其余ego分支比较同一时刻的行人位置，双方发生接触之后的时刻均排除；位移差须同时超过同动作repeat误差和5厘米描述门槛，才计入成对响应覆盖。如果五分支完全相同，仍如实保留事件，但不能计成ego干预产生不同反馈的覆盖证据。这是后果描述，不是正式场景准入门槛。

验证生成器反馈覆盖时，先冻结模板、阶段、seed、配额和覆盖描述门槛，再经普通编译/采集入口执行。报告所有请求、失败候选、修正、通过场景与行为缺额；功能诊断和开发调参样本另列。不能用手改某两景证明普通生成器稳定覆盖，也不能按未来反馈强弱淘汰合法评测样本。控制器版本的资格、普通生成覆盖和完整视觉可见性分别报告。

`vehicle_relations` 是历史兼容的关系/上下文计数：存在前车不等于前车正在限制速度，ego 的信号诊断也不证明该分支服从信号。新增 `reported_npc_rule_triggers` 单列 NPC 已记录的让行、信号和实时车身冲突触发条件及相关对象，计数范围为0≤t<4秒的决策；t=4的命令作用于窗口外，不计入。规则已触发但未列出对象时（如窄路释放确认期间），相关对象记为null，不补猜对象。它不把前车存在或最终 `reason` 字段直接当作主导原因。多个规则可同时触发，而现有日志没有逐规则目标速度变化，因此仍不能从计数确定哪个规则真正进一步降低了目标速度；分析持续等待时须联合轨迹、命令和完整诊断。

行人运动后停住时，还要列出当段策略模式、原生读回的行走命令和剩余路径距离。区分策略命令停步、接近路径终点的零命令、其他模式的零命令，以及“仍有行走命令但物理上停住”。最后一种不能作为主动避让或正常到达终点的证据，也不能仅凭没有车辆碰撞记录就断言不存在地形或静态障碍；具体阻挡原因须另查。

每段事件列出落入其中的2Hz采样时刻。这只说明时间采样支持，不能证明没有遮挡或已经在RGB中看见。视觉小样还须查看原图，并通过原六相机/LiDAR、RGB局部误差和重放门禁。

新版本先独立开发小样：十二模板均有原生物理验收，检查每景六分支及全部10对ego动作、公共历史、repeat、控制重算和实际阶段。再用少量完整视觉小样检查可观察性。没有出现的阶段/反馈明确列为缺口；不把计划分层、控制命令或旧批次结果冒充本次实测覆盖。正式评测的设计配额在开发阶段冻结，合法等待、弱响应及有效动作后的接触按原协议保留。

覆盖中的“事件期成对位置差”可能来自此前运动的累积；它不能单独证明该次停步的起点、时长或控制因ego动作而改变。解释具体反应时，须同时查看分支间决策时序、已执行控制和实际运动。步速分层不预先指定停步、退让或加快结果，合格的无反馈场景仍保留。

联合设计的行人入区/穿越不再要求ego保持匀速也在4秒内入区。布局门禁读取最终冻结的正加速策略，按速度增量上限积分目标速度，并追加0.75秒规划响应预留，要求估计在3秒内到达入口，留下1秒观察时间。仍保存原匀速ETA和独立停车空间约束；其他模板及行人路缘等待/接近清空沿用原匀速4秒门禁。这是采集前的目标速度模型机会，不是原生加速下界或实际3秒到达保证；0.75秒沿用现有规划响应参数，未经加速延迟标定。实际t0机会、全部10对ego动作、执行、公共历史与repeat继续按原门槛验收。完整场景编写后，再由最终出生站位、初速、共同运动时长和动作参数重算该门禁；不复用编写前的相遇估计。旧job缺省阶段/步速先从原slot seed解析并冻结，再变更候选seed。


## 实测相遇时机和动态汇入

新编译规格记录 `measured-encounter-calibration-v1`。依据完整共同历史的实测 t0 速度、路线距离和车身位置，对相对车距、到达时间差或行人清空余量做有界校准。每次只改尚未采集未来的出生布局，另写不可覆盖的新规格并重跑公共历史；最多两次、单次沿路线最多8米。相关车队保持次序，同车道相对距离校准固定 ego 参照。原始提案、所有修订及各自历史完整保留。最终五动作及 QA repeat 必须重放最后冻结的同一历史；禁止在 t0 瞬移或用未来强响应挑选校准结果。

跟驰/变道检查实测相对距离和相对速度；较紧间隙/后车接近分层必须有实际目标道后车。直路汇入检查预计横移中段的相对位置；路口、左转、匝道检查双方到达差；行人入区/穿越检查清空和 ego 接近余量。已停止的对象不套用自由匀速到达公式；路缘等待、已经清空、信号控制和窄路占用仍如实记录，不强制全部落进相遇目标。这些是观测状态的工程估计，不保证未来发生响应或无接触。

`observed-gap-merge-v1` 只用于周车直路汇入。实时投影目标道车辆的车身前后间隙、相对速度和有限匀速外推；间隙不足先留在源车道，持续满足确认时间才开始横移。横移早期如目标间隙关闭且源车道可返回，可取消并平滑返回；返回过程中继续检查源车道。已经明显切入则继续清空目标车道，不能因风险骤增横穿回去。该局部启发式不是碰撞避免保证。匝道仍使用其真实汇流路线及纵向反馈，不冒称新增了双车道横移能力。

保存 `npc_merge_state.json`，包括模型历史之前的观测、逐步决策、−2秒和t0的内部状态；从初始状态复算预热，再复算整个分支，公共历史也比对该证据。`controller_diagnostics.json` 记录实时前后间隙、阻挡对象、等待/开始/取消/完成状态与实际横向进度。观察报告区分策略指令和实际横向运动；只在接触前描述主动响应，不把取消命令自动当作已经回到原车道。

汇入返回使用 `measured-abort-return-v1`：记录中须存在等待到汇入的启动，启动后实际离开源车道中心至少5厘米；随后在已施加的取消策略下，持续至少0.25秒向源中心返回至少5厘米。运动与上一物理步命令对齐，只统计未来且接触前的运动；缺少已记录启动基线时不推断返回。另列是否回到源中心5厘米以内，这仍不等于全车身已完成回道。`observed_progress_decrease` 单独保存横向进度比例下降，可能只是车道内回正，不能计为取消覆盖。以上均是报告描述门槛，不参与场景准入或采样筛选。

该返回描述要求连续各物理步向内移动超过0.1毫米；单帧停顿会切断片段。因此这是连续返回的保守计数，可能漏掉带短暂停顿的真实回程，不能宣称穷尽全部返回行为。
